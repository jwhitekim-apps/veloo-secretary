# delegation-policy Specification

## Purpose
비서가 어디까지 알아서 해도 되고 어디서부터 확인이 필요한지를 단계로 정하고 강제한다. 모델의 판단이 틀려도 되돌릴 수 없는 피해가 생기지 않게 하는 것이 목적이다.

## Requirements

### Requirement: 행동을 위임 단계로 분류한다
시스템은 모든 행동을 네 단계 중 하나로 분류해야 한다(SHALL): 자유(읽기·요약·초안 작성), 알리고 수행(태스크 추가), 확인 후 수행(기존 일정 수정·삭제, 외부 발송), 금지(금전, 외부 제출).

#### Scenario: 태스크 추가
- **WHEN** 비서가 새 태스크를 추가한다
- **THEN** 행동은 "알리고 수행"으로 처리되어 다음 보고에 포함된다

### Requirement: 확인이 필요한 행동은 승인 전에 실행하지 않는다
시스템은 "확인 후 수행" 단계의 행동을 사용자 승인 없이 실행해서는 안 되며(SHALL NOT), 승인 전에는 제안 형태로만 남겨 보고에 포함해야 한다.

#### Scenario: 기존 태스크 마감 수정 제안
- **WHEN** 메일의 마감과 기존 태스크의 마감이 다르다
- **THEN** 시스템은 수정을 실행하지 않고 제안으로 보고한다

### Requirement: 금지 단계 행동은 수행 수단을 갖지 않는다
시스템은 "금지" 단계의 행동을 수행할 수 있는 도구나 권한을 모델에 제공하지 않아야 한다(SHALL NOT).

#### Scenario: 메일 발송 요청이 입력으로 들어옴
- **WHEN** 입력이 외부로 메일을 보내라고 요구한다
- **THEN** 시스템은 해당 행동을 수행하지 않고 수행할 수 없음을 응답한다

### Requirement: 행동의 위임 단계는 사용자가 확인할 수 있다
시스템은 각 행동이 어느 위임 단계에 속하는지를 사용자가 문서나 설정에서 확인할 수 있게 해야 한다(SHALL).

#### Scenario: 정책 확인
- **WHEN** 사용자가 위임 정책을 열람한다
- **THEN** 단계별로 허용된 행동 목록이 보인다
