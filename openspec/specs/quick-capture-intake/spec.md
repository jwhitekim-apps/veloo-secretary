# quick-capture-intake Specification

## Purpose
사용자가 아이폰 단축어 등으로 던진 한 문장, 복사한 텍스트, 화면 이미지를 받아 일정·마감·할 일·메모로 해석하는 입구다. 벨루 모달을 여는 마찰 없이 장부에 쌓이게 하는 것이 목적이다.

## Requirements

### Requirement: 인증된 요청만 수락한다
시스템은 공유 비밀값을 포함한 요청만 처리하고, 그렇지 않은 요청은 내용을 해석하지 않고 거부해야 한다(SHALL).

#### Scenario: 올바른 비밀값
- **WHEN** 유효한 비밀값과 함께 입력이 도착한다
- **THEN** 시스템은 입력을 해석 단계로 넘긴다

#### Scenario: 비밀값 없음 또는 불일치
- **WHEN** 비밀값이 없거나 틀린 요청이 도착한다
- **THEN** 시스템은 거부 응답을 반환하고 모델 호출과 장부 쓰기를 하지 않는다

### Requirement: 텍스트와 이미지 입력을 받는다
시스템은 일반 텍스트(음성 전사 포함)와 이미지 입력을 받을 수 있어야 한다(SHALL). 텍스트는 텍스트 해석 경로로, 이미지는 이미지 해석 경로로 처리한다.

#### Scenario: 음성으로 말한 한 문장
- **WHEN** "금요일까지 교수님 메일 답장"이라는 텍스트가 도착한다
- **THEN** 시스템은 하나의 태스크 후보를 만든다

#### Scenario: 일정이 담긴 화면 이미지
- **WHEN** 일정 정보가 보이는 이미지가 도착한다
- **THEN** 시스템은 이미지에서 읽은 항목을 태스크 후보로 만든다

### Requirement: 문장에서 태스크 필드를 추출한다
시스템은 입력에서 이름, 마감일(YYYY-MM-DD), 우선순위, 시각 등 부가 정보를 추출해야 한다(SHALL). 시각은 메모에 기록하고 마감일 필드에는 날짜만 둔다.

#### Scenario: 시각이 있는 일정
- **WHEN** "다음 주 화요일 3시 랩미팅"이 입력된다
- **THEN** 이름은 "랩미팅", 마감일은 해당 화요일의 날짜, 메모에는 "15:00"이 들어간다

#### Scenario: 우선순위 표현
- **WHEN** 입력에 "급함"이 포함된다
- **THEN** 우선순위는 높음으로 설정된다

### Requirement: 상대 날짜는 요청 시각 기준으로 해석한다
시스템은 "금요일", "이번 주 안에" 같은 상대 표현을 요청이 도착한 시각과 사용자 시간대를 기준으로, 가장 가까운 미래 날짜로 해석해야 한다(SHALL).

#### Scenario: 요일 지정
- **WHEN** 일요일에 "금요일까지"가 입력된다
- **THEN** 마감일은 바로 다음 금요일이다

### Requirement: 불확실하면 되묻지 않고 추정을 알린다
시스템은 정보가 부족할 때 추가 질문 없이 합리적 기본값으로 처리하고, 어떻게 추정했는지를 응답에 포함해야 한다(SHALL).

#### Scenario: 날짜 없는 입력
- **WHEN** "교수님 메일 답장"처럼 날짜가 없는 입력이 도착한다
- **THEN** 마감일 없이 태스크 후보가 만들어지고 응답에 "마감 없음으로 처리"가 명시된다

### Requirement: 오래 걸리는 처리는 먼저 접수하고 결과를 카톡으로 알린다
시스템은 요청이 접수 모드(`async`)를 지정하면 입력을 검사한 뒤 곧바로 접수 응답을 돌려주고, 해석과 저장은 이어서 처리한 뒤 결과를 카톡 나에게 보내기로 알려야 한다(SHALL). 처리가 실패해도 실패를 같은 방법으로 알려야 한다.

#### Scenario: 접수 모드로 보낸 정상 입력
- **WHEN** 접수 모드로 올바른 입력이 도착한다
- **THEN** 해석이 끝나기 전에 접수 응답이 돌아가고, 처리 결과가 나중에 카톡으로 온다

#### Scenario: 접수 모드로 보낸 잘못된 입력
- **WHEN** 접수 모드로 텍스트도 이미지도 없는 입력이 도착한다
- **THEN** 접수하지 않고 곧바로 오류로 응답한다

#### Scenario: 접수 뒤에 처리가 실패함
- **WHEN** 접수한 입력의 해석이나 저장이 실패한다
- **THEN** 실패 내용이 카톡으로 온다

### Requirement: 손글씨 이미지는 더 큰 모델로 다시 읽는다
시스템은 이미지를 기본 모델로 읽은 결과가 손글씨를 포함한다고 표시되고 더 큰 모델이 설정되어 있으면, 그 이미지를 큰 모델로 다시 읽어 그 결과를 써야 한다(SHALL). 인쇄된 글자나 화면 글자뿐인 이미지와 텍스트 입력은 기본 모델 한 번으로 처리한다. 사용자가 고품질(`quality=high`)을 지정하면 처음부터 큰 모델로 읽는다.

#### Scenario: 손글씨가 있는 화면 캡처
- **WHEN** 기본 모델이 이미지에 손글씨가 있다고 판단한다
- **THEN** 큰 모델로 다시 읽은 결과를 사용한다

#### Scenario: 메신저 대화 화면 캡처
- **WHEN** 기본 모델이 이미지에 인쇄된 글자뿐이라고 판단한다
- **THEN** 다시 읽지 않고 기본 모델의 결과를 사용한다

#### Scenario: 큰 모델이 실패함
- **WHEN** 손글씨를 다시 읽는 큰 모델 호출이 실패한다
- **THEN** 기본 모델의 결과를 쓰고 응답에 다시 읽지 못했다고 알린다

#### Scenario: 고품질을 직접 지정함
- **WHEN** 고품질을 지정한 이미지 입력이 도착한다
- **THEN** 처음부터 큰 모델로 한 번만 읽는다

### Requirement: 응답을 문장으로 받을 수 있다
시스템은 요청이 문장 응답(`format=text`)을 지정하면 JSON 대신 문장만 평문으로 돌려줘야 한다(SHALL). 성공, 접수, 오류 응답이 모두 같은 방식을 따른다. 지정하지 않으면 JSON으로 응답한다.

#### Scenario: 문장 응답으로 접수
- **WHEN** 접수 모드와 문장 응답으로 올바른 입력이 도착한다
- **THEN** 평문 문장 "접수했어요. 결과는 카톡으로 보내 드릴게요."가 돌아온다

#### Scenario: 문장 응답에서 인증 실패
- **WHEN** 문장 응답으로 인증 없는 요청이 도착한다
- **THEN** HTTP 401과 "오류: unauthorized" 평문이 돌아온다

### Requirement: 처리 결과를 즉시 응답한다
시스템은 요청 한 번에 대해 무엇을 만들었는지(이름, 마감일, 추정 내역)를 요약한 응답을 반환해야 한다(SHALL).

#### Scenario: 정상 처리
- **WHEN** 입력이 정상 처리된다
- **THEN** 응답은 생성된 태스크의 이름과 마감일, 추정한 항목을 한 문장으로 담는다
