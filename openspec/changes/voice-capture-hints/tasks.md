# Tasks

## 1. 음성 표시 (`quick-capture-intake`)

- [ ] 1.1 입력 처리가 주소의 `source=voice`를 읽어(그 외 값은 무시) 해석 단계로 넘기고, 접수 모드와 동기 모드, 시험 실행(`dry`) 모두에서 같은 값이 전달되게 한다. 검증: 테스트에서 `voice`가 해석 옵션으로 전달되고, 알 수 없는 값과 표시 없음은 이전과 같은 옵션이 된다
- [ ] 1.2 해석 프롬프트에 받아쓰기 규칙(고유명사는 고쳐 쓰지 않고 보이는 그대로, 의심스러운 부분만 추정에 "받아쓰기 오인식 가능: …"을 짧게)을 표시가 있을 때만 붙인다. 검증: 테스트에서 표시가 있으면 프롬프트에 규칙이 있고 없으면 지금과 글자 단위로 같다. 실제 모델 시험(`npm run test:live`)에서 "램미팅 삼공학관" 같은 어색한 입력은 추정에 안내가 붙고 "금요일까지 교수님 메일 답장"은 붙지 않는다

## 2. 보고 시각 표시 (`daily-report`)

- [ ] 2.1 메모 첫 줄에서 시각(`H:MM`, `HH:MM`)을 뽑는 함수를 한 곳에 만들고 `[오늘]`을 시각 순서(시각 없는 항목은 뒤에 입력 순서대로)로 정렬한다. 검증: 테스트에서 15:00, 10:00, 시각 없음이 10:00, 15:00, 시각 없음 순서가 되고, 같은 시각과 시각 없는 항목끼리는 입력 순서가 유지된다
- [ ] 2.2 `classifyOpenTasks`의 임박 항목에 시각을 싣고 `[임박]` 줄에 `이름(10/11 14:00·3일 후)`로 표시한다. 일일 실행 흐름에서 메모가 전달되게 한다. 검증: 테스트에서 시각이 있는 임박 항목에는 시각이 보이고, 메모가 비었거나 시각이 아니면 지금과 같은 줄이다. 모든 말풍선이 200자 이내다

## 3. 문서와 확인

- [ ] 3.1 `docs/shortcut-prompts.md`와 `docs/shortcut.md`의 말하기 단축어 주소에 `&source=voice`를 넣고 동작을 설명하며, `docs/operations.md`의 보고 구성 표에 `[오늘]` 시각 순서와 `[임박]` 시각 표시를 적는다. 검증: 문서의 주소와 설명이 실제 동작과 같다
- [ ] 3.2 배포 후 폰에서 뒷면 탭 말하기로 구두 약속 문장을 실제로 보내 본다. 검증: 알림에 받아쓴 글이 뜨고, 카톡 결과가 오며, 어색한 이름이 섞인 문장에서는 추정 안내가, 평범한 문장에서는 안내 없이 일정만 오고, 다음 아침 보고에서 시각이 보인다(사용자 확인)
