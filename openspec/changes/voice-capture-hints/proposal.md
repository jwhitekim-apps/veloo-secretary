# Proposal

## Why

구두로 잡은 약속은 폰에서 말하기 단축어(음성 받아쓰기)로 넣는다. 그런데 받아쓰기는 이름과 장소를 틀리게 적기 쉽고, 서버는 글로 쓴 것과 받아쓴 것을 구분하지 못해 틀린 이름을 그대로 태스크 이름으로 확정한다. 비서에는 수정 도구가 없어서 한 번 틀리면 사용자가 벨루에서 직접 고쳐야 한다.

또 약속은 몇 시인지가 중요한데, 아침 보고에서 시각이 보이는 곳이 제한적이다. `[오늘]` 구역은 메모 첫 줄(`15:00`)을 이름 옆에 보여 주지만, `[임박]` 구역에는 메모가 전달되지 않아 시각이 사라진다. 그래서 "내일 14시 미팅"이 보고에서는 시각 없는 항목으로 보인다. `[오늘]` 구역도 시각 순서가 아니라 입력 순서로 나열된다.

## What Changes

- 입력 주소에 **`source=voice` 옵션**을 추가한다. 이 표시가 있으면 입력을 음성 받아쓰기 결과로 보고, 이름과 장소가 잘못 인식되었을 수 있다는 점을 해석에 반영한다. 의심스러운 부분은 고쳐 쓰지 않고 보이는 그대로 두며 추정으로 알린다. 알 수 없는 값은 무시하고, 표시가 없을 때의 동작과 응답 형식은 그대로다.
- 아침 보고의 `[임박]` 구역에서도 메모에 시각이 있으면 이름 옆에 보여 주고, `[오늘]` 구역은 시각이 있는 항목을 시각 순서로 앞에 둔다.
- 말하기 단축어의 주소에 `&source=voice`를 붙이도록 문서를 고친다.
- **범위 밖**: 시각을 벨루의 별도 필드로 저장하는 것(벨루 변경이 필요하고 확인 전에는 손대지 않는다), 시각에 맞춘 알림, 받아쓴 글을 사람이 고치는 화면, 되묻는 대화, `[먼저 할 일]`의 시각 표시.

### Modified Capabilities
- `quick-capture-intake`: 음성 받아쓰기로 들어온 입력임을 표시할 수 있고, 표시가 있으면 오인식 가능성을 추정으로 알린다.
- `daily-report`: 시각이 있는 일정은 `[오늘]`과 `[임박]` 구역에서 시각과 함께 보여 주고, `[오늘]`은 시각 순서로 정렬한다.

## Impact

- 코드: `src/http/intake.ts`(옵션 읽기), `src/wire.ts`(해석 단계로 전달), `src/domain/interpret.ts`(프롬프트 규칙), `src/domain/report.ts`(시각 추출, 정렬, 임박 구역 표시), `src/flows/daily.ts`(임박 항목에 시각 전달). 테스트는 `tests/` 아래 같은 경로.
- 문서: `docs/shortcut.md`, `docs/shortcut-prompts.md`, `docs/operations.md`.
- 서버 입력 계약(JSON 본문)과 벨루는 바뀌지 않는다. 새 옵션은 선택이라 기존 단축어는 영향을 받지 않는다.
- 모델 호출: 프롬프트가 조금 길어지는 정도이고, 표시가 있을 때만 규칙이 붙는다.
