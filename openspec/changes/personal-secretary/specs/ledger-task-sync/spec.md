# Spec Delta

## Purpose

해석된 항목을 벨루 장부에 태스크로 반영하되, 비서가 쓴 것과 사용자가 쓴 것을 구분하고 중복·되살림을 막는다. 같은 장부를 읽고 쓰는 구조에서 신뢰를 지키는 것이 목적이다.

## ADDED Requirements

### Requirement: 비서가 만든 태스크에 표식을 남긴다
시스템은 자신이 만든 모든 태스크의 메모에 비서 생성 표식과 출처 식별자를 남겨야 한다(SHALL).

#### Scenario: 메일에서 만든 태스크
- **WHEN** 메일에서 찾은 마감으로 태스크를 만든다
- **THEN** 메모에 비서 표식과 해당 메일의 식별자가 포함된다

### Requirement: 같은 출처로 중복 생성하지 않는다
시스템은 이미 처리한 출처(메일, 입력 요청)로 태스크를 다시 만들지 않아야 한다(SHALL).

#### Scenario: 어제 처리한 메일을 오늘 다시 읽음
- **WHEN** 이미 처리 이력이 있는 메일이 다음 실행에서 다시 조회된다
- **THEN** 새 태스크를 만들지 않는다

### Requirement: 사용자가 지운 태스크를 되살리지 않는다
시스템은 처리 이력을 장부와 별도로 저장하여, 사용자가 비서가 만든 태스크를 삭제해도 같은 출처로 재생성하지 않아야 한다(SHALL).

#### Scenario: 사용자가 삭제한 뒤 다음 실행
- **WHEN** 비서가 만든 태스크를 사용자가 벨루에서 삭제하고 다음 실행이 돈다
- **THEN** 해당 출처에서 태스크가 다시 생성되지 않는다

### Requirement: 사용자가 쓴 태스크를 수정하지 않는다
시스템은 비서 표식이 없는 태스크를 사용자 승인 없이 수정하거나 삭제해서는 안 된다(SHALL NOT).

#### Scenario: 마감이 달라 보이는 기존 태스크
- **WHEN** 메일의 마감과 사용자가 쓴 태스크의 마감이 다르다
- **THEN** 시스템은 태스크를 바꾸지 않고 불일치를 보고에 포함한다

### Requirement: 쓰기 실패를 숨기지 않는다
시스템은 장부 쓰기가 실패하면 성공한 항목과 실패한 항목을 구분해 보고에 포함해야 한다(SHALL).

#### Scenario: 일부 항목 쓰기 실패
- **WHEN** 세 항목 중 하나의 쓰기가 실패한다
- **THEN** 보고는 두 개 성공과 한 개 실패를 구분해 알린다
