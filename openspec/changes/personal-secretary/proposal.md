# Proposal

## Why

벨루 태스크를 거의 쓰지 않는다. 읽기 쪽이 아니라 **입력 쪽 마찰**(모달을 열어 이름·메모·우선순위·마감일을 채우는 일)이 원인이다. 일정과 마감은 메일, 카톡, 머릿속에 흩어져 있고 장부(벨루)에는 쌓이지 않는다. 장부가 비어 있으면 요약·브리핑은 가치가 없다. 입력 비용을 한 문장 말하기 수준으로 낮추고, 스스로 들어오는 정보(메일)는 비서가 장부에 반영해야 한다.

동시에 이 프로젝트는 Claude SDK로 "내 데이터와 도구에 연결되어 사람 없이도 도는 것"을 직접 만들어 보는 연습이다. 핵심 학습 대상은 모델 호출 자체가 아니라 **어디까지 위임하고 어떻게 확인받느냐**의 설계다.

## What Changes

- 개인 비서를 새로 만든다. 벨루를 **중심 장부**로 두고, 입력과 보고 채널을 분리한다.
  - 입력: 아이폰 단축어(Siri 음성 한 문장, 복사한 텍스트, 필요 시 화면 캡처)를 서버로 보내 해석한다.
  - 메일: 개인 Gmail(학교 메일 전달분)을 키워드로 거른 뒤 LLM이 중요도와 마감을 판단한다.
  - 장부 반영: 해석한 결과를 벨루 태스크로 추가한다. 비서가 만든 것임을 표식으로 남긴다.
  - 보고: 카톡 "나에게 보내기"로 한 일을 알린다(출력 전용).
- 위임 범위를 정책으로 명시한다. 읽기·요약·초안은 자유, 태스크 추가는 알리고 수행, 기존 일정 수정·삭제와 외부 발송은 확인 후, 금전·외부 제출은 금지.
- 처리한 메일/입력의 ID를 별도로 기억해, 사용자가 지운 태스크가 되살아나지 않게 한다.
- **범위 밖(이번 change에서 제외)**: 카톡방 대화 읽기(공식 API 없음), arXiv 신규 논문 추천, 폴리오 연동("읽은 시간" 추적 포함), 메신저 양방향 봇, 벨루 DB 스키마 변경.

## Capabilities

### New Capabilities
- `quick-capture-intake`: 단축어 등으로 들어온 자연어·텍스트·이미지를 인증된 요청으로 받아 일정/마감/할 일/메모로 해석한다.
- `ledger-task-sync`: 해석 결과를 벨루 태스크로 쓰고, 비서 생성 표식과 중복 방지를 관리한다.
- `mail-triage`: 개인 Gmail을 읽기 전용으로 키워드 필터링하고 중요 메일의 마감을 추출한다.
- `daily-report`: 정해진 시각에 벨루와 비서의 처리 내역을 모아 카톡 나에게 보내기로 보고한다.
- `delegation-policy`: 비서의 행동을 위임 단계(자유/알리고 수행/확인 후/금지)로 분류하고 강제한다.

## Impact

- 새 코드: 입력을 받는 HTTP 엔드포인트, 정해진 시각에 도는 실행기(스케줄러), Gmail·Supabase·카카오 어댑터, Claude SDK 기반 해석/판단 로직.
- 외부 시스템(읽기/쓰기): 벨루 Supabase(`todos`, `users`), Gmail API(`gmail.readonly`), 카카오 나에게 보내기 API(토큰 갱신 필요).
- 외부 프로젝트: 벨루(`/Users/joon/CODINGPROJECT/veloo`)는 이 change에서 코드 수정 대상이 아니다. 단, 쓰기 경로(Supabase 직접 vs 벨루 백엔드 API)는 확인이 필요하며 이는 design.md의 미정 사항이다.
- 비용·개인정보: 메일과 입력 내용이 LLM API로 전송된다. 본문은 필터를 통과한 메일에 한해 읽는다.
