# 단축어 만들기 프롬프트

아이폰 단축어를 프롬프트로 만들 때 쓰는 글이다. 단축어 세 개(텍스트, 음성, 이미지)를 각각 따로 복사해서 쓴다. 요청 형식과 동작 원리는 `docs/shortcut.md`에 있다.

## 먼저 알아 둘 것

- **공통 주소**: `https://personal-secretary-kappa.vercel.app/api/intake?async=1&format=text`
  - `?async=1`은 서버가 **곧바로 "접수했어요"라고 답하고**, 해석과 벨루 저장은 뒤에서 한 뒤 **결과를 카톡으로 보내는** 방식이다. Siri로 실행한 단축어가 서버 응답을 오래 기다리다 "문제가 발생했습니다"로 실패하는 것을 막는다.
  - 저장하지 않고 시험하려면 주소 끝에 `&dry=1`을 더 붙인다(`...?async=1&format=text&dry=1`). 카톡으로 `[시험: 저장 안 함]` 결과만 온다.
- **비밀값**: 아래 프롬프트의 `<INTAKE_SECRET>` 자리에는 `.env.local`의 `INTAKE_SECRET` 값을 **직접** 붙여 넣는다. 프롬프트 입력창이나 대화에 그 값을 붙여 넣지 말고, 단축어가 만들어진 뒤에 단축어 편집 화면의 헤더 값에 넣는 것을 권한다.
- **공유 금지**: 단축어 안에 비밀값이 들어 있으므로 다른 사람에게 공유하지 않는다.
- **이름**: Siri로 실행하려면 이름을 흔한 낱말로 짓는다. "화면테스트"처럼 단순한 명사는 잘 알아듣고, `추가`, `메모`, `일정`, `알림`처럼 기본 기능을 떠올리게 하는 말이나 만든 말은 잘 못 알아듣는다. 아래 이름은 제안일 뿐이니 직접 말해 보고 되는 이름을 쓴다.
- **응답은 문장으로 받는다 (`&format=text`).** 서버가 JSON 대신 `접수했어요. 결과는 카톡으로 보내 드릴게요.` 같은 **문장만** 돌려준다. 단축어(특히 Siri)가 JSON(사전 형태)을 결과로 보여 주거나 읽다가 실패하는 일이 있어서 만든 옵션이다. 값을 꺼내는 단계는 넣지 않고, "URL 콘텐츠 가져오기"의 결과를 "결과 보기"에 그대로 넘긴다. 오류도 `오류: unauthorized`처럼 문장으로 보인다.
- 프롬프트로 만든 결과가 빠뜨린 동작이 있으면, 각 절 끝의 **수동 동작 목록**을 보고 단축어 앱에서 직접 채운다.

## 1. 텍스트 단축어

키보드로 쓰거나 키보드의 마이크로 말해서 일정을 넣는다. 조용한 곳과 말하기 편한 곳을 둘 다 쓸 수 있다.

**이름 제안**: `문장입력`

```
"문장입력"이라는 단축어를 만들어줘.

동작은 이 순서야:
1. 텍스트 입력창을 띄워서 내용을 입력받는다. 질문 문구는 "어떤 일정인가요?"로 한다.
2. 아래 주소로 POST 요청을 보낸다.
   - URL: https://personal-secretary-kappa.vercel.app/api/intake?async=1&format=text
   - 헤더: Authorization = Bearer <INTAKE_SECRET>
   - 요청 본문: JSON, 키는 text 하나이고 값은 1번에서 입력받은 텍스트
3. URL 요청의 결과(응답 내용)를 그대로 화면에 결과로 보여준다. 응답에서 값을 따로 꺼내지 마.

조건:
- 실행할 때 확인 창이 따로 뜨지 않게 해줘.
- 이 단축어는 다른 사람에게 공유하지 않을 거야.
```

**수동 동작 목록**: ① 입력 요청(텍스트) → ② URL 콘텐츠 가져오기(POST, 헤더 `Authorization`, 본문 JSON `text`) → ③ 결과 보기(URL 콘텐츠를 그대로).

**기대하는 결과**: 화면에 `접수했어요. 결과는 카톡으로 보내 드릴게요.`가 뜨고, 몇 초 뒤 카톡으로 `[비서] 추가했어요 1건: …`이 온다.

## 2. 음성 단축어

말로 일정을 넣는다. Siri나 액션 버튼, 뒷면 탭으로 실행해서 손을 쓰지 않는다.

**이름 제안**: `말하기입력` (Siri가 잘 못 알아들으면 흔한 낱말 두 개를 붙인 이름으로 바꾼다)

```
"말하기입력"이라는 단축어를 만들어줘.

동작은 이 순서야:
1. 텍스트 입력 요청 동작으로 내용을 입력받는다. 질문 문구는 정확히 "어떤 일정인가요?"로 한다.
   (Siri로 실행하면 이 질문을 소리로 묻고, 그다음에 말한 내용을 입력으로 받게 해줘. 받아쓰기 동작은 쓰지 마.)
2. 아래 주소로 POST 요청을 보낸다.
   - URL: https://personal-secretary-kappa.vercel.app/api/intake?async=1&format=text
   - 헤더: Authorization = Bearer <INTAKE_SECRET>
   - 요청 본문: JSON, 키는 text 하나이고 값은 1번에서 입력받은 텍스트
3. URL 요청의 결과(응답 내용)를 그대로 화면에 결과로 보여준다. 응답에서 값을 따로 꺼내지 말고, 소리로 읽지도 마.

조건:
- 실행할 때 확인 창이 따로 뜨지 않게 해줘.
- "Siri야, 말하기입력"이라고 말해도 실행되게 해줘.
- 이 단축어는 다른 사람에게 공유하지 않을 거야.
```

**수동 동작 목록**: ① **입력 요청**(텍스트, 질문: `어떤 일정인가요?`) → ② URL 콘텐츠 가져오기(POST, 헤더, 본문 JSON `text`) → ③ 결과 보기(URL 콘텐츠를 그대로).

**질문이 "텍스트가 어떻게 됩니까?"로 나오면**: 입력 요청 동작의 **질문(프롬프트) 칸이 비어 있다**는 뜻이다. 그 칸에 `어떤 일정인가요?`를 적는다. 질문을 지정하지 않으면 Siri가 기본 질문을 한다.

**왜 "받아쓰기"가 아니라 "입력 요청"인가**: 받아쓰기로 한 번에 말하면 Siri가 문장을 자기 명령으로 해석해서 단축어를 건너뛰는 경우가 있다. 특히 "찾아보기", "검색", "메모", "전화", "알려줘", "타이머" 같은 말이 들어 있으면 그렇다(예: "다른 논문들 더 찾아보기"를 말하면 Siri가 검색이나 메모를 해 버린다). 입력 요청은 Siri가 먼저 질문을 하고 그 **답**을 받기 때문에 명령으로 해석되지 않는다.

**말하는 순서**: ① "Siri야, 말하기입력"이라고 **이름만** 말한다 → ② Siri가 "어떤 일정인가요?"라고 묻는 것을 기다린다 → ③ 그다음에 일정을 말한다. 이름 뒤에 일정을 이어서 말하지 않는다.

**말하는 요령**: "금요일까지 교수님 메일 답장", "다음 주 화요일 3시 랩미팅", "11월 20일이 학회 초록 마감, 급함"처럼 한 문장으로, 날짜와 시각을 같이 말한다. 날짜를 빼면 "마감 없음"으로 저장되고 카톡에 그렇게 알려 준다.

**기대하는 결과**: 화면에 `접수했어요…`가 뜨고, 몇 초 뒤 카톡으로 `[비서] 추가했어요 1건: …`이 온다.

## 3. 이미지 단축어

지금 보고 있는 화면(카톡 대화 등)을 찍어서 일정을 넣는다. **타이핑이 필요 없어서 입력 마찰이 가장 낮다.**

**이름 제안**: `화면던지기` (또는 이미 Siri가 잘 알아듣는 `화면테스트`를 고쳐서 쓴다)

```
"화면테스트"라는 단축어를 만들어줘.

동작은 이 순서야:
1. 지금 화면을 스크린샷으로 찍는다.
2. 그 이미지의 크기를 가로 1000픽셀로 줄인다(세로는 비율대로).
3. 이미지를 JPEG 형식으로 변환한다.
4. 이미지를 Base64 문자열로 인코딩한다. 줄바꿈은 넣지 않는다.
5. 아래 주소로 POST 요청을 보낸다.
   - URL: https://personal-secretary-kappa.vercel.app/api/intake?async=1&format=text
   - 헤더: Authorization = Bearer <INTAKE_SECRET>
   - 요청 본문: JSON, 키는 image 하나이고 값은 4번의 Base64 문자열
6. URL 요청의 결과(응답 내용)를 그대로 화면에 결과로 보여준다. 응답에서 값을 따로 꺼내지 마.

조건:
- 사진 앱에는 아무것도 저장하지 마.
- 실행할 때 확인 창이 따로 뜨지 않게 해줘.
- 이 단축어는 다른 사람에게 공유하지 않을 거야.
```

**수동 동작 목록**: ① 스크린샷 찍기 → ② 이미지 크기 변경(가로 1000) → ③ 이미지 변환(JPEG) → ④ Base64 인코딩(줄바꿈 없음) → ⑤ URL 콘텐츠 가져오기(POST, 헤더, 본문 JSON `image`) → ⑥ 결과 보기(URL 콘텐츠를 그대로).

**꼭 지킬 것**

- **크기 줄이기(2\~3번)를 빼지 않는다.** 서버의 요청 본문 한도가 4.5MB라서, 원본 스크린샷(PNG)을 Base64로 보내면 넘을 수 있다. 가로 1000px JPEG는 약 90KB다.
- **Siri 음성으로 실행하면 Siri 창이 화면 아래쪽에 같이 찍힌다.** 최신 메시지가 화면 아래에 있는 카톡에서는 그 부분이 가려질 수 있다. 이미지 단축어는 **뒷면 탭이나 액션 버튼, 홈 화면 아이콘**으로 실행하는 것을 권한다. 가려진 부분은 서버가 지어내지 않고 카톡 알림에 `읽을 수 없음`으로 알려 준다.
- 카톡 화면에는 다른 사람의 메시지가 보이고 그 내용이 Gemini로 전송된다. \*\*결제가 연결된 프로젝트의 키(유료 등급)\*\*일 때만 입력이 Google 제품 개선에 쓰이지 않는다.

**기대하는 결과**: `접수했어요…`가 뜨고, 약 15초 뒤 카톡으로 `[비서] 추가했어요 N건: …`이 온다(이미지 해석은 시간이 걸리지만 이제 기다리지 않는다).

## 4. 사진(카메라) 단축어

종이 일정표, 손글씨 메모, 포스터, 칠판을 카메라로 찍어서 넣는다. 서버는 이미지가 화면 캡처인지 사진인지 따지지 않으므로, 3번 단축어에서 **첫 단계와 크기만** 다르다.

**이름 제안**: `사진던지기`

```
"사진던지기"라는 단축어를 만들어줘.

동작은 이 순서야:
1. 카메라로 사진을 한 장 찍는다. 후면 카메라를 쓰고, 찍기 전에 카메라 미리보기를 보여준다.
2. 그 이미지의 크기를 가로 1600픽셀로 줄인다(세로는 비율대로).
3. 이미지를 JPEG 형식으로 변환한다. 위치 같은 메타데이터는 유지하지 않는다.
4. 이미지를 Base64 문자열로 인코딩한다. 줄바꿈은 넣지 않는다.
5. 아래 주소로 POST 요청을 보낸다.
   - URL: https://personal-secretary-kappa.vercel.app/api/intake?async=1&format=text
   - 헤더: Authorization = Bearer <INTAKE_SECRET>
   - 요청 본문: JSON, 키는 image 하나이고 값은 4번의 Base64 문자열
6. URL 요청의 결과(응답 내용)를 그대로 화면에 결과로 보여준다. 응답에서 값을 따로 꺼내지 마.

조건:
- 사진 앱에는 아무것도 저장하지 마.
- 이 단축어는 다른 사람에게 공유하지 않을 거야.
```

**수동 동작 목록**: ① 사진 촬영(후면, 미리보기 켬) → ② 이미지 크기 변경(**가로 1600**) → ③ 이미지 변환(JPEG, 메타데이터 유지 끔) → ④ Base64 인코딩(줄바꿈 없음) → ⑤ URL 콘텐츠 가져오기(POST, 헤더, 본문 JSON `image`) → ⑥ 결과 보기(URL 콘텐츠를 그대로). 이미 찍어 둔 사진을 쓰려면 ①을 **사진 선택**으로 바꾼다.

**손글씨는 서버가 알아서 큰 모델로 다시 읽는다.** 실제 손글씨 사진으로 비교한 결과, 가벼운 모델은 가로 1000px든 2000px든 글자를 **잘못 읽고 지어냈고**("뭘 하고 싶은지" → "원인과 필요성"), 큰 모델은 **두 해상도 모두 정확**하게 읽었다. 즉 원인은 해상도가 아니라 모델이다. 그래서 서버는 가벼운 모델이 이미지를 읽으면서 "손글씨가 있다"고 판단하면 큰 모델로 **다시 읽는다**(주소에 따로 붙일 것이 없다). 화면 캡처 단축어와 같은 주소를 쓴다. 손글씨 이미지는 30~40초 걸리지만 접수 모드라 기다리지 않는다. 큰 모델도 같은 사진을 읽을 때마다 결과가 조금 달라질 수 있어서, 알림 끝의 `읽은 내용`으로 확인하는 것이 안전하다. 가로 1600px는 글씨가 작은 종이도 읽히도록 넉넉하게 잡은 값이며, 서버 한도(4.5MB)에 한참 못 미친다.

**잘 읽히게 찍는 요령**
- 종이를 평평하게 두고 **위에서 정면**으로 찍는다(기울어짐이 적을수록 좋다).
- **밝은 곳**에서, 그림자와 반사가 글씨에 지지 않게 한다.
- 글씨가 화면을 **크게** 채우게 찍는다.
- 항목은 **줄을 나눠서** 쓴다(번호, 체크박스, 줄바꿈).

**결과를 믿기 전에 확인하는 법**: 카톡 알림 끝에 `읽은 내용: "..."`이 붙는다. 모델이 이미지에서 **읽은 글을 그대로** 적은 것이라, 손글씨를 잘못 읽었는지 바로 알 수 있다. 읽은 내용이 틀렸으면 태스크 이름도 틀린 것이다.

## 시험하는 순서

1. 각 단축어를 처음 만들 때는 주소를 `...?async=1&dry=1`로 해서 **저장 없이** 시험한다. 카톡으로 `[비서] [시험: 저장 안 함] …`이 오면 단축어, 서버, 해석, 카톡 알림이 모두 이어진 것이다.
2. 결과가 맞으면 `&dry=1`을 지우고 실제로 한 번 보낸다. 벨루에 태스크가 생기고 카톡에 `추가했어요`가 온다.
3. 같은 입력을 다시 보내면 새로 만들지 않고 `이미 있는 일정`이라고 알려 준다(이름과 마감이 같을 때).

## 문제가 생기면


| 증상                 | 원인과 조치                                                                 |
| ------------------ | ---------------------------------------------------------------------- |
| 단축어에서 `401`        | 헤더의 비밀값이 서버의 `INTAKE_SECRET`과 다르다. 앞뒤 공백이 섞이지 않았는지 본다                  |
| `400`              | 본문에 `text`(텍스트·음성) 또는 `image`(이미지) 키가 없다. 키 이름과 값이 맞는지 본다              |
| Siri가 "문제가 발생했습니다" | 주소 끝에 `?async=1`이 있는지 확인한다. 없으면 서버 응답을 오래 기다리다 실패한다                    |
| 접수는 되는데 카톡이 안 온다   | 카톡 알림이 실패한 것이다. 카카오 토큰 문제일 수 있으니 `docs/operations.md`의 "실패가 보이는 곳"을 본다 |
| Siri가 이름을 못 알아듣는다  | 흔한 낱말로 이름을 바꾸거나, Siri 대신 뒷면 탭·액션 버튼·아이콘으로 실행한다                         |
| 손글씨를 잘못 읽는다(예: 논문 → 동물) | 서버가 손글씨로 판단하면 큰 모델로 다시 읽는다. 그래도 틀리면 주소 끝에 `&quality=high`를 붙여 처음부터 큰 모델로 읽히거나 다시 찍는다. 카톡 알림의 `읽은 내용`으로 실제로 어떻게 읽었는지 본다 |
| 일정의 마감이 비어 있다      | 입력에 날짜가 없었거나 이미지에서 읽지 못한 것이다. 카톡 알림의 `추정:`, `읽을 수 없음:`을 본다             |
