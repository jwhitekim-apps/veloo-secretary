# 아이폰 단축어 설정

> 단축어를 프롬프트로 만들 때 복사해서 쓰는 글(텍스트, 음성, 이미지)은 [`shortcut-prompts.md`](shortcut-prompts.md)에 따로 있다.

일정을 벨루에 넣는 입구는 단축어 두 개다. 둘 다 같은 주소로 요청을 보낸다.

| 단축어 | 보내는 내용 | 언제 쓰나 |
|---|---|---|
| 텍스트 | `{"text": "금요일까지 교수님 메일 답장"}` | 머릿속 일정을 말하거나 입력할 때 |
| 화면 | `{"image": "<Base64 JPEG>"}` | 카톡 등 화면에 있는 일정을 옮길 때 |

## 요청 형식

- 주소: `https://personal-secretary-kappa.vercel.app/api/intake`
- 방식: `POST`
- 헤더: `Authorization: Bearer <INTAKE_SECRET 값>`, `Content-Type: application/json`
- 응답: `{"message": "..."}` 한 문장. 단축어는 `message`를 화면에 보여 주면 된다.

`INTAKE_SECRET`은 `.env.local`과 Vercel 환경 변수에 있는 같은 값이다. 단축어를 다른 사람과 **공유하지 않는다**(헤더에 이 값이 들어 있다). 폰을 잃어버리면 두 곳의 값을 함께 바꾼다.

## 텍스트 단축어 만들기

단축어 앱에서 아래 동작을 순서대로 넣는다.

1. **입력 요청**(텍스트): 키보드로 쓰거나 마이크로 말할 수 있다. 받아쓰기만 쓰고 싶으면 "텍스트 받아쓰기"를 넣는다.
2. **URL 콘텐츠 가져오기**: 위 주소, 방식 `POST`, 헤더 두 개, 요청 본문은 JSON으로 `text` 키에 1번의 결과를 넣는다.
3. **결과 보기**(또는 "말하기"): 응답의 `message` 값을 보여 준다.

## 화면 단축어 만들기

1. **스크린샷 찍기**
2. **이미지 크기 변경**: 가로 1000픽셀
3. **이미지 변환**: JPEG
4. **Base64 인코딩**: 줄바꿈 없음
5. **URL 콘텐츠 가져오기**: 위 주소, `POST`, 헤더 두 개, 본문은 JSON으로 `image` 키에 4번의 결과를 넣는다.
6. **결과 보기**: 응답의 `message`

2번에서 줄이는 이유: Vercel 함수의 요청 본문 한도는 4.5MB다. 가로 1000px JPEG는 약 90KB(Base64로 약 120KB)라서 한도에 한참 못 미친다.

## 실행 방법과 이름

- Siri로 실행하려면 이름을 **Siri가 잘 알아듣는 단순한 낱말**로 짓는다. "화면테스트"처럼 흔한 명사 조합은 잘 되고, `추가`, `메모`, `일정`, `알림`처럼 기본 기능을 떠올리게 하는 말이나 만든 말은 잘 안 된다. 직접 말해 보고 되는 이름을 쓴다.
- Siri를 쓰지 않고 **뒷면 탭**, **액션 버튼**, **홈 화면 아이콘**으로 실행해도 된다. 화면 단축어는 Siri 창이 캡처에 같이 찍히므로 이쪽이 더 낫다.

## Siri로 실행할 때는 `?async=1`을 붙인다

해석과 저장에는 텍스트 약 7초, 이미지 14~20초가 걸린다. **Siri로 실행한 단축어는 응답을 이렇게 오래 기다리면 "죄송합니다, 문제가 발생했습니다. 다시 시도하십시오"라고 하며 실패한다**(서버는 정상 처리했는데도 그렇다). 다시 보내면 같은 태스크가 중복으로 생길 수 있다.

주소 끝에 `?async=1`을 붙이면 서버가 **즉시** `접수했어요. 결과는 카톡으로 보내 드릴게요.`라고 답하고(HTTP 202), 해석과 벨루 저장은 뒤에서 이어서 한 뒤 **결과를 카톡 나에게 보내기로 알려 준다**. 처리가 실패해도 카톡으로 온다.

- 주소: `https://personal-secretary-kappa.vercel.app/api/intake?async=1`
- 단축어 마지막 단계의 "결과 보기"는 접수 문장만 보여 주면 된다. 실제 결과는 카톡에서 본다.
- 시험할 때는 `?async=1&dry=1`로 보낸다. 저장하지 않고 `[비서] [시험: 저장 안 함] ...` 알림만 온다.
- 같은 이름·같은 마감의 태스크를 비서가 이미 만들어 두었으면 다시 보내도 새로 만들지 않고 "이미 있는 일정"이라고 알린다.

## 시험 모드

주소 끝에 `?dry=1`을 붙이면 **해석만 하고 아무것도 저장하지 않는다**. 응답은 `[시험: 저장 안 함] ...`으로 시작한다. 단축어를 처음 만들 때 실제 벨루를 건드리지 않고 시험하는 용도다.

## 응답 시간

텍스트는 약 7초, 이미지는 약 15초 걸린다(Gemini 호출 시간). 단축어가 그만큼 기다린다.

## 응답 읽는 법

| 응답 | 의미 |
|---|---|
| `추가했어요 N건: ...` | 벨루에 저장됨 |
| `벨루에 저장하지 못했어요(...): ... 직접 추가해 주세요.` | 일정은 읽었지만 벨루 서버에 닿지 않음. 다음 아침 보고에도 실패로 올라온다 |
| `비슷한 일정이 이미 있어서 수정은 제안으로만 남겼어요` | 같은 이름의 내 태스크가 있어서 새로 만들지 않음. 아침 보고의 "확인" 항목으로 나온다 |
| `추정: ...` | 입력에 없는 정보를 기본값으로 정한 경우(예: 날짜 없음 → 마감 없음) |
| `읽을 수 없음: ...` | 이미지에서 가려지거나 잘린 부분. 지어내지 않고 알려 준다 |

HTTP 오류: `401`은 헤더의 비밀값이 서버와 다름, `400`은 본문에 `text`나 `image`가 없음.

## 개인정보

보낸 텍스트와 이미지는 Gemini API로 전송된다. **결제가 연결된 프로젝트의 키(유료 등급)**여야 입력이 Google 제품 개선에 쓰이지 않는다(무료 등급은 쓰일 수 있다고 약관에 있다). 카톡 화면에는 다른 사람의 메시지가 보이므로, 무료 키라면 화면 단축어를 쓰지 않는다.

## 이미지 해석 시험 결과 (task 3.4)

개인정보가 없는 가짜 카톡 화면(일정 3개 포함)을 직접 그려, 단축어와 같은 처리(가로 1000px JPEG)를 거쳐 실제 Gemini에 보냈다. 기준 시각은 2026-10-07(수).

| 시험 화면 | 결과 |
|---|---|
| 평범한 화면 | 랩미팅(10/13, 15:00, 3공학관 201호), 중간 보고서 초안 제출(10/9), 학회 초록 마감(11/20) 3건을 모두 맞게 추출. 오른쪽이 잘린 메시지는 "읽을 수 없음"으로 보고 |
| 아래쪽을 Siri 창처럼 가린 화면 | 가려진 마지막 메시지의 일정(11/20)은 **지어내지 않고** "하단 Siri 창으로 가려진 메시지"를 읽을 수 없음으로 보고하고 빼 버림. 나머지 2건은 맞게 추출 |

참고: 잘린 글자 뒤를 `201호`처럼 그럴듯하게 보충하는 경우가 한 번 있었다. 장소 같은 부가 정보는 한 번 눈으로 확인하는 편이 좋다. 해석 시간은 이미지 한 장에 약 15초였다. 실제 카톡 화면과 실제 폰 단축어로의 시험은 사용자가 직접 한다.
